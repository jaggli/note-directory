Redesign brief

Why the chrome changes, what replaces it, and every decision with its reason. Each row stands on its own and can be rejected without the rest falling over. The editor, vim, the markdown renderer, the drawing engine, storage, sync and the link format stay as they are — this is about how you reach them.

What is wrong today

Collected from the running app, the help notes and an inventory of index.html, app.js and draw.js. The look is the smallest part: what makes note feel unfinished is structure — commands with no home, things that vanish, words that change.

1

Commands live in four places, each half-complete

The top bar's menu (15 items, app and note mixed, no shortcuts), the sidebar's + ▾, the status bar's new ▾ — the same thing with different behaviour: one starts a rename, the other doesn't — and the status-bar shortcut hints. Phones add four more items to the menu. Nothing is searchable: :mddemo exists only for vim users.

2

You can't see where you are

The open note's name appears only in the sidebar, which is hidden on phones and when collapsed. The top bar says menu and three tabs. Saved, syncing or failed is never shown next to the note.

3

Deleting is inconsistent and permanent

A note with content asks first, an empty one disappears without asking, and neither can be undone — while deleted text and shapes can. Ctrl+Shift+D deletes a note; Ctrl+D duplicates a shape. Rename can't be cancelled with Esc and takes duplicate names.

4

Things disappear instead of explaining

share vanishes from the menu once a note passes 60 kB. Replace, vim, wrap and the cursor position vanish in preview and drawings, so the status bar jumps. A drawing in source mode has no tab back. The sync menu's connect is never shown.

5

One situation, several words

note, file, text, text note. update / new file for a link or dropped file, skip / keep both / override for a zip, silent (conflict) copies for Drive. view for markdown, draw for drawings. Help points to “file → source” and “download zip”, which don't exist.

6

Feedback in six places

A blocking modal, a bottom-right toast in a different font, a button whose label turns into copied!, a fixed label in zen, red text in the vim bar, a yellow badge on the canvas. Modals are sentence case with periods, toasts lowercase, tooltips capitalised.

7

Two searches that overlap

Ctrl+F opens a modal list of matching lines — not the find bar every editor has — while Ctrl+H opens a separate find bar. An all checkbox switches one into the other.

8

Shared links write to your notes without asking

Opening anyone's link adds it to your list. Only a name clash asks. For an app whose promise is privacy, the list should only change when you say so.

9

Phones are second class

Import is drag-and-drop only. Tab nesting for lists can't be reached on a phone keyboard. Mobile help promises “long press to pin or delete” — there is no long press. Vim can arrive through Drive settings sync and can't be turned off on touch.

10

Everything at the same volume

Every label is lowercase Victor Mono, so buttons read as text (menu) and text reads as buttons. The wordmark is the largest thing on screen. Shortcut hints are permanent ads. Nothing reads as the primary action.

The new model

Every region answers one question. Left: what notes do I have — and the state of all of them (sync, storage). Top: which note is this — its name and state, how you look at it, and the ways out (Share, Zen, ⋯). Middle: the note. Bottom: where is my cursor — facts and toggles for the editor. Anything without a button is one ⌘P away, and every menu shows its shortcut.

Left out on purpose

Folders and tags. Search, pins and kind icons carry a flat list a long way; folders are a data-model change, not a design one.

Split edit + preview. Edit ⇄ Preview keeps scroll position already; a split doubles the layout cases for phones.

Open questions for review

  • Undo toast or a “Recently deleted” section? The toast covers the accident; a trash covers “I deleted it yesterday”. The tombstones are there either way.
  • Sans chrome vs all-mono identity. I recommend sans for chrome; the whole system works in mono too if you want the old character — flip --n-font to see.
  • Format on save default. Kept on to match today; I'd turn it off for non-markdown-native users, but that's your call.
