Color and themes

The five themes stay. What changes is that the UI never reads a palette colour directly: it reads a semantic token, and every token is derived from the palette in tokens.css. A theme is twenty hex values, nothing more. Switch the theme at the top to see every token move.

Surfaces

Three levels. The sidebar sits lowest, the page you write on above it, and menus, popovers and the palette float on top. Hover, pressed and lines are translucent text, so they work on any surface.

Panel--n-panelSidebar, settings nav
Page--n-bgEditor, preview, canvas
Raised--n-raisedMenus, popovers, dialogs
Field--n-fieldInputs, segmented track
Hover--n-hoverRows, ghost buttons
Selected--n-selectedActive row, palette hit
Line--n-lineDividers
Strong line--n-line-strongOutlines on raised

Text

Three steps. Text-3 is the gutter colour, not overlay0: it keeps 11 px captions above 4.5:1 in every theme.

Text--n-textContent, labels
Text 2--n-text-2Secondary, idle icons
Text 3--n-text-3Captions, keys, meta

Meanings

One hue per meaning, the same role in every theme. Blue is the only accent; it marks the primary action, selection and focus — never decoration.

Accent--n-accentPrimary, selection, focus
Accent soft--n-accent-softBanner, scope chip
Danger--n-dangerDelete, failed
Warning--n-warningConflict, storage high
Success--n-successSynced, vim insert
Pin--n-pinPinned
Inverse--n-inverseToast, tooltip

Note kinds

The kind icon in the list, the palette and the title bar takes its colour from the extension. Plain text stays grey so colour means something.

Markdown--n-kind-md.md
Drawing--n-kind-draw.draw
Code--n-kind-code.js .sh .yaml …
Text--n-kind-text.txt and the rest

The five themes

Same tokens, five palettes. Latte is the light theme; Match system in Settings pairs it with a dark one.
